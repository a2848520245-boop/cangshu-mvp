# 演示说明

> 面向读者：评审者 / 使用者。目的是一条命令跑起来、五分钟看完原型验证的四件事。
> 本页只描述**可丢弃演示原型**，不是 M1 设计文档；与 [开发宪章](开发宪章.md)、[MVP-SPEC](MVP-SPEC.md) 配套。

## 一、这是什么

「上传 → 存元数据 → 列表 / 详情 → 下载 → 删除」的最小可交互闭环，按 2026-09-15 沟通的 MVP 口径（上传 / 查看 / 下载 / 删除）交付。

仓库地址：<https://github.com/a2848520245-boop/cangshu-mvp>

## 二、演示环境与数据位置

- **只有两个前置条件**：JDK 21、Maven；不需要 Docker、不需要装数据库、不需要联网。
- **应用与数据分离**：上传的文件和数据库都放在独立的数据目录（默认是仓库目录下的 `cangshu-data`，可用环境变量指到仓外），仓库代码可以随时删掉重来。

| 内容 | 默认路径（相对仓库目录） |
| --- | --- |
| 上传的文件 | `<仓库目录>/cangshu-data/files/<32 位随机名>` |
| H2 数据库 | `<仓库目录>/cangshu-data/db/cangshu.mv.db` |

> `cangshu-data` 是**演示数据目录，可整体删除**，删掉后下次启动自动重建空库。
> 删除操作只清理系统内的副本与数据库记录；**上传前您磁盘上那份原文件从未被系统接管，不受影响**（页面的删除确认框里也写了这一句）。
> 想把数据放到仓库之外：启动前设 `$env:CANGSHU_DATA_DIR = "<你的数据目录>"`，代码与配置都不用改。

## 三、启动步骤

```powershell
# 1) 指定 JDK 21（只要求版本是 21，发行版不限；按你的安装路径替换）
$env:JAVA_HOME = "<你的 JDK 21 路径>"
#    若 PATH 上的 java 不是 21，第 3 步改用 "<你的 JDK 21 路径>\bin\java"

# 2) 在仓库根目录打包（跳过单元测试；原型以验收脚本为准，见第六节）
mvn -DskipTests package

# 3) 启动
java -jar target\cangshu-mvp-0.0.1-SNAPSHOT.jar
```

浏览器打开 <http://127.0.0.1:8080/>。停止服务用 `Ctrl+C`。

> 开发期也可以直接 `mvn spring-boot:run`，省掉打包两步。
> 端口被占用时，改 `src/main/resources/application.yml` 里的 `server.port` 即可。

## 四、5 分钟演示步骤

| 步 | 操作 | 看什么（一句话解释） |
| --- | --- | --- |
| 0（30 秒） | 打开 <http://127.0.0.1:8080/> | 单页中文界面，无前端框架、无打包；列表为空或显示已有样本 |
| 1（60 秒） | 选一个**中文名**的文件拖入上传区（例如 `仓鼠演示-2026-09-17.txt`） | 上传区出现该文件的 SHA-256；列表自动刷新并出现新行 |
| 2（45 秒） | 复制列表行的 SHA-256，或点「详情」看完整 64 位值 | 摘要是**边收边算**的：不把整个文件读进内存，大文件也不吃内存 |
| 3（60 秒） | 点「下载」，把文件存到桌面后用 `Get-FileHash` 对比两端摘要 | 下载内容与上传内容**字节级一致**（下载响应里也带 `X-Content-SHA256`） |
| 4（45 秒） | 点「删除」，确认框里会写「原文件不受影响」 | 记录消失，且磁盘上的物理副本同时清理（见下方复核命令） |
| 5（60 秒） | 复核数据目录与整体清理 | 数据都在库外，可整体删除；删掉后重启自动重建 |

第 4、5 步的复核命令（另开一个终端）：

```powershell
# 4) 删除后物理副本应同时消失（数量与库内记录一致）
(Get-ChildItem 'cangshu-data\files' -File).Count

# 5) 整体清理：先停掉进程，再删目录（下次启动自动重建）
Remove-Item -Recurse -Force 'cangshu-data'
```

**刻意不做的**（原型阶段的范围约束）：预览 / 缩略图、逻辑删除与回收站、用户与权限、去重、数据库迁移工具、对象存储、前端框架。逐条理由见 [开发宪章](开发宪章.md) 第 1 节。

## 六、验收脚本跑法

原型不写单元测试，用两套脚本做端到端验收。**先把应用启动起来**（见第三节），再另开一个终端执行。

### 6.1 接口冒烟：24 项

```powershell
node tools/smoke-test.mjs
```

覆盖：中文名与二进制文件上传 → 列表 → 详情 → 下载（本地与远端 SHA-256 相同）→ 删除（记录消失且物理文件消失），即 [开发宪章](开发宪章.md) 第 5 节的 1～4 项。
脚本逐步打印 `PASS` / `FAIL`，最后打印「全部通过：24 项」；任一项失败退出码为 1。
可传自定义地址：`node tools/smoke-test.mjs http://127.0.0.1:8080`；物理文件目录默认按脚本位置推导为 `<仓库目录>/cangshu-data/files`，用环境变量 `CANGSHU_FILES_DIR` 可显式指定（数据目录改用 `CANGSHU_DATA_DIR` 时需同步设置）。

### 6.2 页面交互端到端：12 项

```powershell
# 依赖：Python 3.12 + playwright（chromium 通道使用本机 Edge）
python target\ui-e2e.py
```

覆盖：遮罩层不挡点击、上传后列表出现该行、上传区回显摘要、详情模态含完整 SHA-256 与中文名、关闭按钮生效、下载字节一致、删除后行移除、确认框写明「原文件不受影响」、行数回到上传前。
最后打印「全部通过：12 项」，并在 `target/ui-after.png` 留一张整页截图。

> 该脚本当前只存在于本机 `target/` 构建产物目录（不在仓库版本控制内，因为 `target/` 被忽略）。
> 截图只是现场取证，不作为交付物。

## 七、已知边界

1. **可丢弃原型**：按 [开发宪章](开发宪章.md) 第 1 节的定义，原型弃用即作废，不维护向后兼容。
2. **不是 M1 基线**：原型不决定 M1 的技术栈与结构，只用来暴露问题、验证闭环可达。
3. **数据是演示数据**：`cangshu-data` 只用于演示，没有备份与迁移价值，可整体删除。
4. **单机单进程**：H2 文件模式不支持多进程同时打开；同时开两个实例会报「Database may be already in use」。
5. **无鉴权**：任何能访问 8080 端口的人都能上传 / 下载 / 删除，仅限本机演示，不对外暴露。
6. **删除是物理删除**：原型没有回收站，删掉的记录与副本不可恢复（这与 M1 的「逻辑删除 + 延迟回收」不同）。
7. **接口与字段**：JSON 字段 camelCase、时间为 ISO-8601 UTC、`sha256` 仅作完整性校验，**不作唯一键、不去重**。
8. **不引入数据库迁移工具**：建表读 `src/main/resources/schema.sql`，每次启动重新执行。

## 八、M1 会继承什么

原型本身作废，但它验证过的东西会进 M1。

**直接继承（已验证可用的结论）**

| 项 | 内容 |
| --- | --- |
| 接口契约 | 上述五个接口的方法 / 路径 / 状态码语义、camelCase + ISO-8601 UTC 的 JSON 约定、统一的 `{"code","message"}` 错误响应 |
| 数据模型骨架 | 资源记录与「落盘名服务端生成、原始文件名只进库」的分离（M1 会扩成 Resource / Blob / Location 三层身份） |
| 流式上传落盘流程 | 边收边算 SHA-256 → 先写临时文件 → `ATOMIC_MOVE` 到最终名 → 落库失败删掉已落盘文件 |
| 删除顺序 | 先删物理文件、再删记录，避免「库里有、盘上无」 |
| 页面口径 | 全程中文界面、删除确认明示「不动原文件」 |
| 验收方法 | 用可重复的端到端脚本验收（原型是 24 + 12 项脚本），而不是口头「我跑通了」 |
| 工程基线 | Java 21 + Spring Boot + Maven 的构建与运行方式 |

**M1 要换掉的**

| 项 | 原型 | M1 |
| --- | --- | --- |
| 数据库 | H2 文件模式 | PostgreSQL |
| 建表方式 | 启动时执行 `schema.sql` | 按 M1 定案的迁移方案 |
| 部署 | 本机 `java -jar` | Docker Compose（应用 + PostgreSQL） |
| 前端 | 单页原生 HTML | Vue 3 + TypeScript + Vite |
| ORM | MyBatis-Plus | MyBatis 与 JPA 对比后定案（内部决策记录：未结项） |
| 删除语义 | 物理删除 | 只移除逻辑引用，内容按引用延迟回收 |
| 存储按键 | 随机名直存 `files/` | 内容寻址键 `sha256/ab/cd/<完整摘要>` |
| 内容去重 | 不去重，同哈希允许多条 | 相同内容只保存一份物理副本 |

> 技术栈与范围的事实源是项目内部决策记录（不进本仓库），与本页不一致时以内部决策记录为准。
