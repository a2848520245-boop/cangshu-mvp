# 开发宪章（MVP 原型）

> 适用范围：`cangshu-mvp` 仓库。本文是原型阶段的自我约束，不是 M1 基线；原型弃用即作废。

## 1. 目标与非目标

**目标（只做这一件事）**：跑通「上传 → 存元数据 → 列表/详情 → 下载 → 删除」最小闭环，让导师能当场点开页面、上传文件、下载校验、清理数据。

**非目标（原型阶段刻意不做）**

- 预览、缩略图、在线打开
- 逻辑删除 / 回收站（原型一律物理删除）
- 用户、权限、多租户、审计日志
- 去重（哈希只作完整性校验，**不作唯一键**）
- Flyway / 数据库迁移（2026-09-11 导师原话：「前期不用引入它」）
- 对象存储（MinIO 等）、分片上传、断点续传
- 前端框架与前端构建工具链

## 3. 数据与文件位置

- 上传文件：`E:\AgentWork\CangShu\cangshu-data\files\<32位随机名>`（原始文件名只进数据库，不参与落盘路径）
- 数据库：`E:\AgentWork\CangShu\cangshu-data\db\cangshu.mv.db`
- 清理方式：停掉进程后 `Remove-Item -Recurse -Force E:\AgentWork\CangShu\cangshu-data`，下次启动自动重建
- 落盘名一律服务端生成，用户输入永不进路径 —— 原型阶段即杜绝路径穿越
- 删除只清理系统内副本与记录；**用户上传前位置的原文件不受影响**（它从未被系统接管）

## 4. 代码与接口约定

- JSON 字段 camelCase；时间一律 ISO-8601 UTC（如 `2026-09-16T02:00:00Z`）
- 哈希：SHA-256 小写十六进制；**不唯一、不合并**，仅作完整性校验
- 错误响应统一 `{"code": "...", "message": "..."}`，HTTP 状态码表达语义
- 接口清单以 `README.md` 为准；改接口先改 README

## 5. 验收口径（缺一不算完成）

1. 上传：中文名文件与二进制文件都能上传成功
2. 列表 / 详情：字段与上传结果一致
3. 下载：字节级一致，本地与远端 **SHA-256 相同**
4. 删除：记录消失 **且物理文件从 `files` 目录消失**
5. 全程中文界面，本地 `http://127.0.0.1:8080/` 可用
